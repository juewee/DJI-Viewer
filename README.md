# DJI Footage Viewer · 大疆素材浏览器

一个**本地网页版**的大疆（DJI）素材浏览 / 筛选 / 预览工具。扫描存储卡里的 `DCIM` 目录后，
按拍摄日期归类，自动读取每段素材的分辨率、帧率、编码、位深、HDR、码率、时长等信息，
并用 ffmpeg 抽取缩略图与时间轴抓帧。界面是 DJI 风格的暗色主题，鼠标键盘都能操作。

* 技术选型：**Python 3 标准库**（`http.server`，零第三方依赖）+ **原生 ES Module 前端**（无构建步骤）+ **ffmpeg/ffprobe**。
* 只读：只读目录结构与视频元数据，缩略图写在 `djiviewer/cache/`，绝不修改原始素材。

![界面结构] 左侧日期与概览 → 顶部搜索与筛选 → 中间素材墙 → 右侧详情与预览

## 1. 快速开始

### 前置条件
| 依赖 | 说明 |
| --- | --- |
| Python | 3.9 以上（`python --version` 能跑即可） |
| ffmpeg / ffprobe | 需要能从 `PATH` 找到；也可设 `FFMPEG_HOME`，或把可执行文件放进 `djiviewer\bin\` |

自检环境是否就绪：

```powershell
cd djiviewer
python -m djiviewer --check
```

### 三种启动方式

```powershell
# 1) 双击（最简单）
启动.bat

# 2) 直接指定素材目录并自动开浏览器
python -m djiviewer --dir "G:\DCIM\DJI_001"

# 3) 把目录拖到 打开素材目录.bat 上
```

启动后会自动打开 <http://127.0.0.1:8777/>，按 `Ctrl+C` 停止服务（或直接关掉那个命令行窗口）。

> **端口被占用会自己往后找**：8777 → 8778 → 8779 …（默认最多试 12 个），
> 所以重复双击不会失败，命令行里会打印实际使用的地址。
> 内部使用 `SO_EXCLUSIVEADDRUSE` 独占端口，避免 Windows 下两个实例抢同一端口互相打架。

常用参数：

| 参数 | 作用 |
| --- | --- |
| `-d, --dir` | 启动时打开的素材目录 |
| `-p, --port` | 起始端口，默认 `8777` |
| `--port-tries` | 端口被占用时最多往后试几个（默认 12；填 0 表示不重试） |
| `--no-browser` | 不自动打开浏览器 |
| `--root` | 限制可访问的根目录（可重复；默认不限制，仅本机可访问） |
| `--verbose` | 打印访问日志 |
| `--check` | 只做环境自检（含默认端口是否空闲） |

## 2. 界面怎么用

**① 选目录** — 左侧会自动列出本机各盘的 `DCIM` 目录（如 `G:\DCIM\DJI_001`），点一下即可；
也可以手动粘贴路径。勾选「包含子目录」可一次扫描 `DJI_001`、`DJI_002`…全部素材。

**② 参数分析：默认「点开才分析」**

扫描只做两件轻活：读目录、把相机自带的缩略图复制过来。**参数分析（分辨率/帧率/编码/时长）默认不预跑**，
所以你扫完目录不会听到风扇起飞——点开哪条，才读哪条（单条实测 0.4 秒）。

筛选栏的「参数分析」下拉有三档：

| 档位 | 行为 | 适合 |
| --- | --- | --- |
| **点开才分析**（默认） | 只有打开详情时才读该条参数；筛选里的分辨率/帧率/编码暂时为空 | 只想快速浏览，机器要留着干别的 |
| 只分析屏幕里的 | 滚动到哪就分析哪几条，最多 2 条/次，停手就停 | 想用分辨率/帧率筛选，但不想整批跑 |
| 全部分析 | 扫描后按日期由近到远把所有素材读一遍 | 一次性整理、要完整统计 |

另外两个按钮随时可用：「分析可见」（把当前屏幕上的读一遍）、「全部分析」（读全部）。

> **为什么默认不预跑？** 实测 8 并发全量分析时整机 CPU 冲到 **80%**（4K HEVC 解码 + ffprobe），
> 那十几秒里做别的事就会卡。现在默认并发降到 3、每次只分析 1 条，**点开才读**时后台开销是 0。

**（如果需要全量）后台仍是两阶段，阶段①不跑完阶段②不开始：**

| 阶段 | 做什么 |
| --- | --- |
| ① 出图 | 先给**每一个**素材贴缩略图（第一张通常 1~2 秒内出现） |
| ② 分析 | 再逐个 ffprobe 读分辨率/帧率/编码/时长，按日期由近到远 |

出图的优先级：

1. 素材旁边有 `.SCR`（1280×720）或 `.THM`（256×144）→ **直接复制**，毫秒级，不解码；
2. 没有预览图，但有配对的 `.LRF`（720p H.264）→ **拿 LRF 抽一帧**，比解 4K/8K HEVC 快约 3 倍；
3. 都没有 → 才直接对原片抽一帧。

进度条分两段显示：`① 正在贴缩略图 23/118` → `② 按日期由近到远分析 12/118`。
图片是**边生成边贴上**的（前端每 0.9 秒问一次 `/_api/thumb_status`），不用等整批跑完。

> **缩略图和 LRF 预览会不会吃内存？** 不会。缩略图是磁盘上的 JPEG（cache/thumbs），浏览器只缓存已解码的那几张；
> LRF 预览是 **HTTP Range 流式**读文件，播多少读多少，不整段进内存。
> 真正吃 CPU 的只有两件事：**抽缩略图那一帧解码**、以及 **ffprobe 读容器头**。所以把这两件事
> 改成"用时才做"，机器就安静了。

> **为什么不用硬件解码出图？** 实测单帧抓取硬解反而更慢：4K HEVC 779ms（软解）vs 948ms（硬解），
> 720p LRF 263ms vs 648ms——硬解初始化开销比解一帧本身还大。

结果按「路径 + 大小 + 修改时间」缓存，**第二次打开瞬时完成**（几百条素材约 300～700 ms）。

> 顺带一个好处：如果你把 `.THM`/`.SCR` 单独拷到一个目录（例如 `E:\MISC\THM\DJI_001`），
> 这个目录**单独也能当素材库浏览**——缩略图、拍摄时间、序号、日期分组都正常，
> 卡片上会标「SCR 预览图」，只是不能播放（那些文件只有一张图），扫描也几乎不需要分析时间。

**③ 筛选**

| 维度 | 说明 |
| --- | --- |
| 日期 | 左侧日期树多选；也可用「日期范围」下拉 |
| 分辨率 | 只列出素材里真实存在的档位：8K / 5.2K / 4K / 2.7K / 1080P / 720P |
| 帧率 | 23.976 / 25 / 29.97 / 30 / 50 / 60 … |
| 编码 | H.265 / H.264 … |
| 类型 | 视频 / 照片 / 仅 LRF 的条目 |
| 属性 | HDR·10bit、有 LRF 预览、无 LRF、含音频、异常·空文件、未分析 |
| 时长 / 体积 | 滑杆设下限，如「时长 ≥ 60s」「体积 ≥ 500MB」 |
| 快捷 | 4K 及以上、8K、≥50fps、时长 ≥ 1 分钟、体积 ≥ 500MB、今天 |
| 搜索 | 文件名、序号、日期、色彩后缀，大小写不敏感 |

**④ 预览播放** — 点任意卡片打开右侧详情。播放源可三选：

| 源 | 用途 |
| --- | --- |
| **原始 MP4** | 原画质（4K/8K HEVC 是否可播取决于浏览器与显卡的解码能力） |
| **LRF 预览** | 大疆自带的低码率代理（一般是 720p H.264），**秒开、省带宽**，勾选「优先 LRF」可默认走它 |
| **实时转码** | 浏览器解不了 HEVC 时，服务端用 ffmpeg 实时转成 H.264 720p 流式播放 |

HEVC 播放失败时界面会自动弹出提示并提供一键切换；详情里还有「时间轴抓帧」条，点缩略图直接跳到该时间点。

| 操作 | 快捷键 / 方式 |

**⑥ 勾选系统的设计**

勾选与筛选是**两个正交的动作**，互不干扰：

* **点日期文字** = 按该日期筛选（缩小看到的内容）；**点日期前的勾选框** = 选中该日期下「通过当前筛选」的素材。
* 勾选框有三态（全选 / 半选 / 未选），筛完之后一眼看出哪天选了、哪天没选全。
* 「☑ 选中筛选结果」只作用于**当前筛选出来的**素材——这是最常用的组合：先筛出 4K / ≥50fps / 某几天，再一次全选。
* 「⇄ 反选」同样只作用于筛选结果，适合「这批里除了几条以外都要」。
* 选择条实时显示：勾了多少条、总体积、其中**可转存的原片有多少个**（LRF 不计入）。

**⑦ 连拍照片：一组一张卡**

无人机/运动相机的连拍、包围曝光会在同一秒内连拍多张，文件名只差末尾的帧号：

```
DJI_20261017144148_0065_D_001.JPG   ← 第 1 张
DJI_20261017144148_0065_D_002.JPG
…
DJI_20261017144148_0065_D_010.JPG   ← 第 10 张
```

这些照片用**同一个基准名**（`DJI_20261017144148_0065_D`），工具据此把它们识别为一组（≥2 张才算）：

* 网格里**折叠成一张卡**，背后画出叠层，左上角标 `连拍 10`，右下角显示 `1/10`；
* **鼠标悬停**会在组内自动逐张预览（每 0.62 秒换一张），快速扫一眼这 10 张拍得怎么样；
* 卡片上的勾选框**一次选中整组 10 张**（导出一组就是导出全部原片），部分选中时显示半选态；
* 右下角 **「摊开」** 把这一组拆成 10 张独立卡片，逐张挑、逐张勾；拆开后每张的 `连拍 3/10` 角标**点一下就收回整组**；
* 详情抽屉顶部有**胶片条**，一眼看到整组，点任意一张直接跳过去，`←` `→` 也能逐张切换；
* 顶部筛选栏的 **「合并成组」** 开关可以全局关掉（关掉后就是 10 张独立卡片），选择会被记住。

> 统计栏会显示「连拍：4 组 / 40 张」，一眼知道这批素材里有多少是连拍。
> 折叠**只影响显示**——数据仍是一条素材一个文件，筛选、勾选、转存、体积统计全部按真实文件数算。

## 2.5 转存（导出原始素材）

选中素材后点批量条上的 **「转存原始素材…」**（或按 `e`）：

* **只导出原片**：MP4 / MOV / JPG / DNG；**LRF 预览代理与 SCR/THM 相机缩略图都不导出**，
  面板上会写明「你勾了 N 条素材、其中 M 个原片」。
* **目标文件夹**：可直接粘贴路径；也可点「浏览…」用内置目录浏览器逐层选择（磁盘根 / 上一层 / 可用空间）。面板会给出建议路径（源目录同级的 `DJI_001_export`）并记住上次用过的位置。
* **结构选项**：按日期建子文件夹（默认开）、保留原目录名（`DJI_001`）、写导出清单 CSV、重名时覆盖 / 跳过 / 自动改名。
* **动手前先看清单**：点「预览清单」做一次干跑——文件数、总体积、涉及天数、目标磁盘可用空间、重名冲突数、0 字节文件数、源文件缺失告警。空间不足或目标不可用会直接禁用「开始转存」。
* **实时进度**：进度条 + 一行统计（文件数、已写/总量、百分比、**实时速度**、**剩余时间估算**、已用时、当前文件名）。字节进度是**正在拷贝的文件实时累加**的，所以几百 GB 的批量也能看到进度在走，不用等单文件拷完。
* **随时可停**：「停止」在当前文件的拷贝过程中即时生效（毫秒级），并**删除没拷完的半截文件**，不会留下损坏素材。
* **失败可追**：失败的文件会列出文件名 + 原因（最多显示 6 条），并可 **「下载失败明细 CSV」** 逐条核对；清单 CSV 里也记录了每个文件的结果。
* **完成后**：可「打开目标文件夹」；面板会记住**最近用过的导出目录**（最多 8 个），下次一点即用。

转存是**拷贝**而非移动，原始素材始终不动；只有目标目录已存在同名文件时才按所选策略处理。

## 3. 它识别什么

**文件名规则**（大疆通用命名）：

```
DJI_20260927142658_0002_D.MP4
│   │              │    └─ 后缀：D = D-Log M 色彩；_001/_002 = 分段序号
│   │              └────── 媒体序号（与同名 .LRF 成对）
│   └───────────────────── 拍摄时间 YYYYMMDDHHMMSS（以文件名为准，最可靠）
└───────────────────────── 前缀
```

* `.MP4` 与同名 `.LRF` 视为**同一条素材**（成对展示，界面标 `LRF` 角标）；
* 只有 `.LRF` 没有 `.MP4` 的条目会标记「仅 LRF」；
* `.SCR`（1280×720）/ `.THM`（256×144）是**相机自带的预览图**，自动配对到同一条素材、
  直接用作缩略图，并在详情抽屉里作为附加文件列出（标「SCR 预览图 / THM 缩略图」）；
* 照片末尾多一段 `_001 … _010` 的是**连拍/包围曝光的帧号**，会归成一组（见 ⑦），单张不受影响；
* `.JPG` 照片也会列出，可直接预览；
* 0 字节文件标为「异常」并给出原因，不会让扫描中断；
* 除文件名外，还会从容器里读取：编码器型号（如 `DJI OsmoAction6`）、时间码、色彩传递特性等。

分辨率档位由实际宽高判定（`3840×2160 → 4K`、`7680×4320 → 8K`…），并给出宽高比与像素量；
HDR 判定综合 `color_transfer` / `color_primaries` / 10bit 像素格式与 profile。

## 4. 目录结构

```
djiviewer/
├─ 启动.bat / 打开素材目录.bat     # 双击即用
├─ djiviewer/                     # 后端（Python 标准库）
│  ├─ __main__.py                 #   CLI 入口
│  ├─ config.py                   #   配置、ffmpeg 定位（PATH / FFMPEG_HOME / bin）
│  ├─ parser.py                   #   DJI 文件名解析、分辨率/HDR 分类、格式化
│  ├─ ffmpeg.py                   #   ffprobe 探测、抽帧、缩略图、实时转码
│  ├─ scan.py                     #   目录扫描 + MP4/LRF 配对 + 统计聚合
│  ├─ cache.py                    #   探测缓存 + 缩略图 + 后台线程池队列
│  ├─ export.py                   #   转存：计划/干跑、分块拷贝、进度、取消、清单
│  └─ server.py                   #   HTTP 服务：API、Range 视频流、静态页
├─ web/                           # 前端（原生 ES Module，无构建）
│  ├─ index.html · favicon.svg
│  ├─ css/style.css               #   DJI 风格暗色主题
│  └─ js/{app,store,core,gallery,drawer,exporter,api,utils}.js
├─ tools/
│  ├─ cli.py                      # 命令行扫描/探测/筛选演示
│  ├─ e2e_test.py                 # 端到端接口测试（含 Range 逐字节校验）
│  ├─ e2e_export_test.py          # 转存端到端测试（逐字节校验/排除 LRF/取消/重名策略）
│  ├─ check_web.py                # 前端 DOM 引用与 CSS 静态核查
│  ├─ test_boot.mjs               # 前端启动链路冒烟测试（DOM 桩，无需浏览器）
│  ├─ test_core.mjs               # 前端筛选/排序/分组/勾选逻辑单测（真实数据）
│  └─ dump_fixtures.py            # 导出单测数据
└─ cache/                         # 缓存目录（可随时删除）
   ├─ probe_cache.json            #   探测结果
   └─ thumbs/*.jpg                #   缩略图
```

## 5. 后端接口（前端就是这么调的）

| 接口 | 说明 |
| --- | --- |
| `GET /_api/info` | 环境信息、ffmpeg 路径与版本、可用 DCIM 根目录 |
| `GET /_api/scan?folder=&recursive=1` | 扫描目录，返回素材条目 + 统计 + 待探测清单 |
| `POST /_api/meta` `{paths,enqueue}` | 批量取已缓存的探测结果，并可把缺失的排进后台队列 |
| `GET /_api/progress` | 后台进度（含 `phase` / `thumb_total` / `thumb_done`） |
| `POST /_api/thumb_status` | 查询这批文件里哪些缩略图已经能看了（前端边生成边贴图） |
| `GET /_api/frames?path=&t=&w=` | 抓取指定时间点的单帧 JPEG |
| `GET /_thumb/<name>?path=` | 缩略图（可为生成的 jpg，或相机自带的 SCR/THM 直出） |
| `GET /_media/<abs-path>` | 原始文件流，**支持 Range**（206 / `Content-Range` / 后缀 Range） |
| `GET /_live/<abs-path>` | ffmpeg 实时转码 fMP4 流（MSE 播放） |
| `POST /_export/` `{paths}` | 导出 CSV（UTF-8 BOM，Excel 直接打开） |
| `GET /_api/reveal?path=` · `GET /_api/open?path=` | 资源管理器定位 / 系统默认程序打开 |
| `POST /_api/export` `{paths,dest,dryRun?,byDate?,keepDirName?,conflict?,manifest?}` | 转存原始素材；`dryRun:true` 只返回计划 |
| `GET /_api/export/progress?job=` | 转存进度（文件数/已写字节/百分比/速度/剩余时间/失败明细/日志） |
| `POST /_api/export/cancel` `{job}` | 停止转存（拷贝过程中即时生效，并清理半截文件） |
| `GET /_api/export/report?job=` | 下载失败明细 CSV |
| `GET /_api/browse?path=` | 目录浏览（网页版"选择文件夹"，含可用空间与磁盘根） |
| `GET /_api/suggest_dest?folder=` | 建议的导出目标目录 + 历史记录 |
| `POST /_api/delete` `{paths,confirm:true}` | 删除文件（界面需二次确认） |
| `POST /_api/cache/purge` | 清空缓存 |

服务默认只监听 `127.0.0.1`，局域网内其他机器访问不到。

## 7. 常见问题

**页面打开了，但点「扫描目录」没反应 / 界面是空壳**
说明前端脚本没跑起来。现在界面右下角会直接弹出红色提示说明原因（脚本加载失败 / 脚本报错 /
6 秒内没启动），照着提示处理即可。绝大多数情况按 `Ctrl+F5` 强制刷新就好——浏览器缓存了旧版模块。
若提示「模块加载失败」，打开浏览器控制台（`F12` → Console）把红色报错发我，那是最直接的线索。

**播放器提示「浏览器无法直接解码」但它其实在播 / 蒙版挡住画面**
现在的规则是：**只要有"确实在播"的证据（`playing` / `timeupdate` 事件，或时间轴在走），蒙版立刻消失**，
不再依赖 `readyState` 数值（部分浏览器解码 HEVC 时这个值长期偏低，画面其实正常——这是踩过的坑）。
另外还有一层兜底：打开素材时会用 `canPlayType()` 探测浏览器是否支持该编码，
**不支持就直接自动切到 LRF 预览并给出小字说明**，不弹蒙版打扰你。
只有 8 秒内完全没有任何播放证据，或者浏览器明确报解码错误（`MediaError.code = 4`）时，才会显示提示。

**补充说明**：4K/8K 10bit HEVC 依赖硬件与浏览器解码能力。若你的机器只能出声音、画面卡住，
用 LRF 预览（720p H.264，秒开）或实时转码是最稳的两条路；
也可以在卡片/详情里直接用系统播放器打开原文件。

**找不到 ffmpeg**
把 `ffmpeg.exe`、`ffprobe.exe` 放到 `djiviewer\bin\`，或设置环境变量 `FFMPEG_HOME` 指向 bin 目录，
或把它们加入 `PATH`。`python -m djiviewer --check` 会直接告诉你找到没有。

**第一次打开卡片信息空着**
正在后台分析。看右上角进度条；分析完会写入缓存，下次打开立刻就有。
想立刻拿到全部信息，先跑一次 `python tools/cli.py probe "目录"` 预热缓存。

**端口被占用**
不用管——会自动往后换端口，命令行里会打印实际地址。也可以显式指定：`python -m djiviewer --port 8899`。

**双击 `启动.bat` 一闪而过、端口没起来**
已修。原因是 `.bat` 曾被写成 **LF 换行**，而 cmd.exe 解析 `if (...)` 这类括号块要求 CRLF，
会把一行拆成多条命令（表现为 `'not' is not recognized` 之类的报错然后静默退出）。
现在两个 .bat 都是 **CRLF + 无 BOM**，并已用 `cmd.exe` 实测通过。
如果你自己改这些脚本，务必保持 CRLF 换行——用记事本另存为 ANSI/UTF-8 时注意换行符选项。

**想清掉缓存**
界面左下角「清空缓存」，或直接删除 `djiviewer\cache\` 目录。原始素材不受影响。

**中文乱码（命令行）**
启动脚本已设 `PYTHONUTF8=1`；手动运行时先执行 `chcp 65001` 或设置该环境变量。

## 8. 安全与只读说明

* 默认不限制可访问路径，但服务只绑定 `127.0.0.1`；需要更严的限制时用 `--root`。
* 所有路径请求都做**真实路径解析 + 白名单根目录**校验，拒绝 `..` 穿越与越权访问（已在 e2e 测试中覆盖）。
* 程序不会修改、移动、重命名任何素材；唯一写操作是「导出 CSV」（浏览器下载）与
  「删除文件」（需界面二次确认，且仅删除你明确勾选的条目）。
